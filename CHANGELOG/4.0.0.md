# 4.0.0

This release makes every `TimeFrame` method return a new TimeFrame rather than changing the TimeFrame in place, which
changes the flagging API. It also adds support for irregular time series (data with no expected spacing, such as
manual gaugings), and replaces `calculate_min_max_envelope()` with a general time-of-year aggregation.
Polars 2 is now supported.

This is the first release published to [PyPI](https://pypi.org/project/ukceh-time-stream/), as
`ukceh-time-stream`.

## Breaking changes

### Every TimeFrame method returns a new TimeFrame

Methods that changed the TimeFrame in place and returned `None` now leave it unchanged and return a new TimeFrame, so
the result must be assigned, e.g. `tf = tf.add_flag(...)`.

- `add_flag()`, `remove_flag()` and `sort_time()` return a new TimeFrame.
- `register_flag_system()` has been removed. Use `with_flag_system()`, which takes the same arguments and returns a
  new TimeFrame.
- `register_flag_column()` and `init_flag_column()` have been replaced by `with_flag_column(column_name,
flag_system_name, data=None)`, which returns a new TimeFrame:
    - For an existing column, it registers the column as a flag column, keeping its values (as
      `register_flag_column()` did), unless `data` is given, which replaces them.
    - For a new column, it creates the column from `data`, or from the flag system's empty value (as
      `init_flag_column()` did).
    - `column_name` is now required and comes first. The automatic `__flag__<flag_system_name>` column name has been
      removed.
    - Using the time column as a flag column raises `ColumnTypeError`.
- The first argument of `remove_flag()` has been renamed from `column_name` to `flag_column_name`, matching
  `add_flag()`.

```python
# 3.x
tf.register_flag_system("CORE_FLAGS", {"OUT_OF_RANGE": 1, "SPIKE": 2})
tf.init_flag_column("CORE_FLAGS", "flags")
tf.add_flag("flags", "SPIKE", pl.col("value") > 100)

# 4.0
tf = tf.with_flag_system("CORE_FLAGS", {"OUT_OF_RANGE": 1, "SPIKE": 2})
tf = tf.with_flag_column("flags", "CORE_FLAGS")
tf = tf.add_flag("flags", "SPIKE", pl.col("value") > 100)
```

### Min-max envelope replaced by time-of-year aggregation

- `calculate_min_max_envelope()` and the `time_stream.calculations` module have been removed. Use
  `time_of_year_aggregate()` (see below), calling it once for `"max"` and once for `"min"`:
  `tf.time_of_year_aggregate("max", "flow").time_of_year_aggregate("min", "flow")`. The result columns follow the
  `aggregate()` naming, so `flow_max` and `flow_min` become `max_flow` and `min_flow`, alongside `time_of_max_flow`,
  `time_of_min_flow` and the usual `count_`, `expected_count_` and `valid_` columns.

### Default periodicity without a resolution

- A TimeFrame created with neither `resolution` nor `periodicity` is now irregular, rather than having a periodicity
  of one microsecond. Its `periodicity` is `None`, and `pad()` and `infill()` raise `PeriodicityError`. Give a
  `resolution` or `periodicity` to keep the previous behaviour.
- `TimeFrame.periodicity` is now typed `Period | None`, being `None` for an irregular TimeFrame.

### Custom aggregation functions

- `AggregationFunction._requires_padding` has been renamed to `requires_padding`. Custom aggregation functions that
  set it need updating. A new `requires_periodicity` class variable marks functions that can't be used on irregular
  data.

### Quality control

- `ComparisonCheck` with `"is_in"` now converts `compare_to` to the column's type, so e.g. integers can be compared
  against a float column, and raises `TypeError` if the values can't be converted.

## New features

### Irregular time series

- `periodicity="irregular"` creates a TimeFrame for data with no expected spacing between values, such as manual
  gaugings or spot samples. `resolution` keeps its meaning as the precision of the timestamps, which must still align
  to it. The new `is_irregular` property tells you whether a TimeFrame is irregular, and `with_periodicity("irregular")`
  also works.
- `aggregate()` works on irregular data, giving a regular TimeFrame at the aggregation period with a null
  `expected_count_<time>`. The `"available"` and `"na"` missing criteria work; `"percent"` and `"missing"` raise
  `MissingCriteriaError`, and `mean_sum` and `nth` raise `AggregationError`, as they need an expected count.
  `time_window` works as normal. Aggregating to `"irregular"` raises `AggregationPeriodError`.
- `rolling_aggregate()` works on irregular data, keeping the input timestamps and staying irregular. `center`
  alignment works with any fixed-length window.
- `qc_check()` works as normal on irregular data.
- `pad()` and `infill()` raise `PeriodicityError`, as there are no expected time steps.
- New user guide page: "Irregular Time Series".

### Time-of-year aggregation

- New `time_of_year_aggregate()` method, which aggregates each time of year across years, e.g. every 1 January in a
  daily series. The result for each time of year is added beside the original values, so the TimeFrame keeps its rows
  and temporal properties. Most aggregation functions are supported (not `mean_sum` or `nth`), along with:
    - `missing_criteria`, measured against the time steps each time of year covers across the reference interval.
    - `aggregation_period`, to group more values together, e.g. `"P1D"` for 15-minute data aggregates each day of the
      year.
    - `reference_interval`, to aggregate only part of the data, e.g. a 1991-2020 climatology. The results are still
      given on every row.
    - `leap_day` (`"separate"`, `"merge"` or `"drop"`), for how 29 February is handled.
- Calls can be chained to add several results, passing `columns` to each.
- New user guide page: "Time of Year Aggregation".

## Installation

Time-Stream can now be installed from PyPI, as `ukceh-time-stream`:

```bash
pip install ukceh-time-stream
```

or with uv:

```bash
uv add ukceh-time-stream
```

It is still imported as `time_stream`. Installing from the git repository still works, but is no longer needed.
`isoperiod` no longer has to be installed
from git separately when using pip.

## Packaging

- The package (distribution) name is now `ukceh-time-stream`, as `time-stream` is taken on PyPI. A project that
  depends on `time-stream` from git should change the dependency to `ukceh-time-stream`. The import name is unchanged.
- Each release merged to `main` is now built and published to PyPI automatically, using trusted publishing.
- Package metadata now includes keywords.
- The README links to `LICENSE`, `CONTRIBUTING.md` and `CITATION.cff` are now full URLs, so they work on the PyPI
  project page.

## Documentation

- The README and installation guide now install from PyPI instead of the git repository.

## Maintenance

- Supports Polars 2. The minimum supported version is still `polars>=1.43.2`
- `isoperiod` is now installed from PyPI rather than from GitHub.
- `make clean` also removes docs builds.
- Numerous dependency and GitHub Actions bumps across the project.
