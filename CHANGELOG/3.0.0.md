# 3.0.0

This release includes various bug fixes that have some minor breaking changes.  It also makes time zone handling
explicit: a time column must now be either without a time zone or in UTC (due to complexities in dealing with
time-zone/daylight saving times).

## Breaking changes

### Time zones

- The time column must be a `Date` or `Datetime` column, and a `Datetime` must either have no time zone or be in UTC.
Any other time zone raises `ColumnTypeError` when the TimeFrame is created. Time zones with daylight saving gave wrong
results, as their days are not all 24 hours long (e.g. aggregating hourly `Europe/London` data to daily counted 24
values in a 23-hour day). Convert with `.dt.convert_time_zone("UTC")`, or keep local clock times with
`.dt.replace_time_zone(None)`. `Time` and `Duration` columns, which previously failed with a Polars error, are
also rejected explicitly on initialisation.
- Datetimes passed in must match the time column they are compared with: without a time zone if it has none, or in
UTC if it is in UTC. This applies to `pad()`, `observation_interval` on `qc_check()` and `infill()`, `RangeCheck`,
`TimeRangeCheck` and `ComparisonCheck`, and a mismatch raises `TypeError`. A time of day (`time_window`, `RangeCheck`)
must not have a time zone. The time column of an `AltData`/`AltDataDynamic` `alt_df` must have the same type as the
TimeFrame's, otherwise `ColumnTypeError` is raised.

### Aggregation results

- `aggregate()` now includes every period between the first and last, including periods with no data, which have a
null value, a count of 0 and `valid_<column>` of `False`. Previously these periods were left out, so
`missing_criteria` could never flag them.
- `sum`, `conditional_count` and `pot` now give null rather than 0 for a period whose values are all null, consistent
with the other aggregation functions.
- `nth` now selects the nth time step of each period, not the nth row, so gaps in the data no longer shift the
result. A missing time step gives a null value, with `time_of_nth_<column>` set to that time step. This applies to
both `aggregate()` and `rolling_aggregate()`. With a `time_window`, `n` counts time steps within the
window, and an `n` larger than the window raises `AggregationPeriodError`.
- `angular_mean` gives null rather than 0.0 for a period with no values.
- `missing_criteria=("percent", n)` now requires at least `n`% of values to be present, rather than more than `n`%,
so a complete period is valid at `("percent", 100)`.

### Rolling aggregation

- `center` alignment now requires the window to span an odd number of time steps, and raises `AggregationError`
otherwise, because a window of an even number of time steps has no single centre time step.

### Exceptions

- A period of the wrong type (e.g. `aggregate(5, ...)`) now raises `TypeError` everywhere, rather than
`PeriodValidationError` in some places.
- A resolution or periodicity that isn't epoch agnostic (e.g. `PT5H`) now raises `ResolutionError` or
`PeriodicityError` rather than `NotImplementedError`, so it can be caught as a `TimeStreamError`.
- String parameters typed as `Literal` (`time_anchor`, `on_duplicates`, `on_misaligned_rows`, `alignment`, `closed`,
`flag_type`, `window_side`) now raise `ValueError` for a value that isn't one of the options, instead of accepting it
silently.
- A time column containing nulls now raises `NullTimeValueError` when the TimeFrame is created.
- `RangeCheck` with `min_value` and `max_value` of different types raises `TypeError` when it is created, rather than
when it is applied.

### Padding

- `pad()` truncates a `start`/`end` that isn't on the time grid to the time step containing it, so the result always
passes validation, and raises `TypeError` for a `date` rather than a `datetime`.

## Other changes

### Core

- A time column with millisecond precision was rejected with `ResolutionError` when `time_anchor="end"`, and with
`on_misaligned_rows="resolve"` every row was silently removed. Alignment checks now give the same result at any
precision.
- `with_df()` sorts the new DataFrame by time.
- `select()` no longer changes the caller's list of column names, and keeps each flag column's decoded state.
- TimeFrame metadata and column metadata are now copied when set, so later changes to the caller's dicts don't affect
the TimeFrame.
- `copy()` no longer re-runs time validation on a TimeFrame that is already valid.

### Quality control

- `ComparisonCheck(flag_na=True)` now flags NaN as well as null values in float columns.
- `RangeCheck` and `TimeRangeCheck` no longer change their own attributes when checking a time range that crosses
midnight.

### Infilling

- `infill()` raised `TimeMutatedError` when the data had missing rows; it now pads the data first.
- `infill(max_gap_size=0)` filled every gap instead of none; it now fills none, and a negative value raises
`ValueError`.

### Flagging

- `add_flag()` and `remove_flag()` treat a null value in a bitwise or list-mode categorical flag column as having no
flags set. Previously `add_flag()` did nothing on null rows.

### Padding

- `pad()` works on a `Date` time column and on a single-row TimeFrame.

## Maintenance

- Added `py.typed`, so type checkers use Time-Stream's type hints.
- Added a lower bound of `numpy>=2.0`, and fuller package classifiers.
- README: corrected the install instructions and added installing with pip; updated the feature overview and the
developer setup commands.
